# Deploying MGK Pharmacy

| Part | Where | Notes |
|---|---|---|
| Database | **Neon** (Postgres) | `production` branch for the live site, `dev` branch for your computer |
| Backend (`apps/api`) | **Render**, free plan | Sleeps after ~15 min idle; the next request takes ~1 min to wake it |
| Uploads (prescriptions, IDs, receipts) | **Cloudflare R2** | Private bucket; files are only served through the API |
| Website (`apps/web`) | **Vercel** | Forwards `/api/*` to Render, so sign-in cookies stay on your domain |
| Mobile app | Built with the Render address | No USB cable or `adb reverse` needed any more |

Do the steps in order. Keep a note of each value marked 📋, you'll paste it later.

---

## 1. Neon: the database

1. In Neon, **New project**: name `mgk-pharmacy`, Postgres 17, region **AWS Europe Central (Frankfurt)**.
2. The project starts with a branch called `production` (or `main`). That's the live database.
3. **Branches → New branch** from it, called `dev`. That's the one your computer uses.
4. For **each** branch, open **Connect** and copy two strings:
   - with **Connection pooling ON** 📋 `DATABASE_URL` (host contains `-pooler`)
   - with **Connection pooling OFF** 📋 `DIRECT_URL`

   Add `&connect_timeout=15` to the end of both (Neon pauses idle databases; this gives it time to wake).

### Point your computer at the `dev` branch

Put the **dev** branch strings in `apps/api/.env` (replace the old `DATABASE_URL="file:./dev.db"` line):

```
DATABASE_URL="postgresql://...-pooler.../neondb?sslmode=require&connect_timeout=15"
DIRECT_URL="postgresql://.../neondb?sslmode=require&connect_timeout=15"
```

Then load the test data and catalogue, exactly like before:

```bash
npm run setup -w apps/api
npm run import:mgk -w apps/api -- --demo-stock
npm run dev
```

`setup` wipes the database it points at. If that database already has data it asks you to type `RESET` first. **Never type RESET with the production strings in `.env`.**

---

## 2. Cloudflare R2: private file storage

1. Cloudflare dashboard → **R2** → **Create bucket**: name `mgk-uploads`, location hint **Eastern Europe** or **Western Europe**. Leave public access **off**.
2. R2 → **Manage API tokens** → **Create API token**:
   - Permissions: **Object Read & Write**
   - Specify bucket: **mgk-uploads** only
3. Copy, they're shown once:
   - 📋 `R2_ACCESS_KEY_ID`
   - 📋 `R2_SECRET_ACCESS_KEY`
   - 📋 `R2_ACCOUNT_ID`: the long ID in the endpoint `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`

---

## 3. GitHub: put the code online (private)

The website and API deploy from GitHub. From the `mgk` folder:

```bash
git init
git add .
git status
```

Check that `git status` does **not** list any `.env` file, `*.db` file or anything in `apps/api/uploads/` (they're excluded by `.gitignore`). Then:

```bash
git commit -m "MGK Pharmacy platform"
git branch -M main
```

Create a **private** repository on GitHub (no README), then:

```bash
git remote add origin https://github.com/<you>/mgk-pharmacy.git
git push -u origin main
```

## 4. Production database: tables, delivery zones, catalogue, first admin

Run these **from your computer, once**, against the **production** branch. Temporarily put the **production** strings in `apps/api/.env`, run the commands, then put the **dev** strings back.

```bash
npm run db:migrate -w apps/api
npm run init:store -w apps/api
npm run import:mgk -w apps/api
npm run create-admin -w apps/api -- --email you@example.com --first Ukashah --last Sahabi
```

1. The first command creates the tables.
2. The second loads the delivery zones and fees.
3. The third loads the 6,498 products **without** demo stock: real stock is counted and received in admin.
4. The last creates your administrator and prints a **one-time password** in your terminal. You choose your own password at first sign-in.

Do **not** run `npm run setup` here: it creates the test accounts whose passwords are in `.env.example`.

---

## 5. Render: the backend

1. Render → **New → Blueprint** → connect GitHub → pick the repository. Render reads `render.yaml` and proposes the `mgk-api` service (free plan, Frankfurt).
2. Fill in the values it asks for:

| Key | Value |
|---|---|
| `DATABASE_URL` | Neon **production**, pooled |
| `DIRECT_URL` | Neon **production**, direct |
| `WEB_ORIGIN` | your Vercel address. Use `https://example.com` for now; it's fixed in step 7 |
| `PAYSTACK_SECRET_KEY` | your Paystack **test** key for now (`sk_test_...`) |
| `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` | from step 2 |
| `BANK_NAME`, `BANK_ACCOUNT_NAME`, `BANK_ACCOUNT_NUMBER` | the pharmacy's real account |
| `STORE_LAT`, `STORE_LNG` | the store's exact coordinates (right-click it in Google Maps) |

`JWT_SECRET` and `PROXY_SECRET` are generated by Render. Leave them.

3. **Apply**. The first build takes a few minutes.
4. Copy the service address 📋 `https://mgk-api-xxxx.onrender.com` and open `/health` on it. It should show `{"ok":true}`.
5. In the service's **Environment** tab, reveal and copy 📋 `PROXY_SECRET`.

---

## 6. Vercel: the website

1. Vercel → **Add New → Project** → import the GitHub repository.
2. **Root Directory**: `apps/web`. The framework is detected as Next.js; leave the build settings alone.
3. **Environment Variables**:

| Key | Value |
|---|---|
| `API_URL` | the Render address, no trailing slash |
| `PROXY_SECRET` | the same value as on Render |
| `NEXT_PUBLIC_SITE_URL` | `https://<project>.vercel.app`, or your own domain later |

4. **Deploy**, then copy the address 📋 `https://<project>.vercel.app`.

---

## 7. Connect them

1. Render → `mgk-api` → **Environment**: set `WEB_ORIGIN` to the Vercel address and save. It redeploys by itself.
2. Paystack dashboard → **Settings → API Keys & Webhooks**:
   - Webhook URL: `https://<render-address>/payments/paystack/webhook`
   - (The callback URL is set by the API per order; nothing to enter.)
3. Open the Vercel address. The first visit may take about a minute while Render wakes up. Sign in with your admin email and one-time password, then choose your own.

### Check it all works

- [ ] Home page and shop load, and search finds "coartem"
- [ ] Register a customer, place an order with a **Paystack test card**, and the order shows "Paid"
- [ ] Upload a prescription; in admin it opens (that proves R2 works)
- [ ] Admin → Staff & roles: add a rider, dispatch the order, and the rider app shows it

---

## 8. Mobile app

Build it against the live API:

```bash
cd apps/mobile
flutter build apk --release --dart-define=API_URL=https://<render-address> --dart-define=DEV_TOOLS=false
```

The APK is in `build/app/outputs/flutter-apk/app-release.apk`. Before publishing to the Play Store, set up release signing (see `apps/mobile/README.md`).

---

## Afterwards

- **Updates:** `git push` redeploys both automatically. New database changes come as Prisma migrations; Render applies them during the build.
- **Going live with payments:** swap `PAYSTACK_SECRET_KEY` on Render for the live key once a test order has worked end to end.
- **Staying awake:** on the free plan the API sleeps when idle. Changing `plan: free` to `plan: starter` in `render.yaml` (paid) keeps it on.
- **Own domain:** add it in Vercel, then update `NEXT_PUBLIC_SITE_URL` (Vercel) and `WEB_ORIGIN` (Render).
- **Still to do before real customers:** the `PLACEHOLDER` contact details in `apps/web/lib/site.ts` and `apps/mobile/lib/core/config.dart`, a real email/SMS provider (`apps/api/src/lib/mailer.ts`), and a paid map-tile provider.
